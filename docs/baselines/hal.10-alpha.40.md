# Distribution baseline `hal.10-alpha.40`

## Trigger

The corrective installer bound an independently reviewed artifact hash to a
source CI run, but did not validate the local packager record. The deterministic
build epoch now makes that record meaningful and allows the candidate bytes to
be tied to their exact local provenance before any device contact.

## Contract

- Build metadata has one strict schema covering version, development channel,
  full source commit, commit-derived epoch, main configuration, versioned
  filename, size, MD5, SHA-256, pinned ESPHome image and ESP-IDF version.
- The checker recomputes both artifact digests and size, derives the epoch from
  the supplied commit and rejects symlinked, empty, renamed or mutated artifacts.
- Corrective readiness requires this metadata in addition to manifest, incident,
  old/new artifacts and hashes, and exact successful source CI.
- The installer validates the entire binding before its explicit confirmation;
  metadata is never trusted merely because it was generated by the packager.

## Validation

- Positive fixtures accept one exact deterministic artifact record.
- Negative fixtures mutate every metadata field, commit, artifact bytes and
  schema and require rejection.
- Corrective fixtures additionally reject wrong commit, epoch and artifact hash
  inside otherwise valid deployment inputs.
- No device, network upload, channel publication, secret rotation or incident
  sealing is performed. The historical endurance remains untouched.
