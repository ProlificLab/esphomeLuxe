# Distribution baseline `hal.10-alpha.24`

## Scope

- Seal the core-canary record from reviewed metrics and seven exact raw logs.
- Derive candidate version/SHA, clean source commit and rollback identity rather
  than trusting manually entered values.
- Repeat the 24-hour readiness and retained `hal.6` artifact checks.
- Refuse overwrite and publish only with an atomic validated no-clobber link.

## Safety contract

- Draft metrics remain human-reviewed; pass status, identity and all hashes are
  generated by the sealer.
- Logs must be non-empty, distinct and inside the output evidence directory.
- Validation occurs on an `fsync` temporary file in the destination directory.
- Any preflight, schema, metric, path or hash failure removes the temporary file
  and leaves no sealed output.
- There is no overwrite option and no network, OTA or restart action.

## Validation

- Seven sealer tests cover successful derivation, overwrite and race refusal,
  missing and external logs, invalid metrics, untrusted draft identity, cleanup
  and CLI preflight ordering.
- The existing eight core-evidence and forty-seven promotion tests remain
  mandatory in CI.
- Physical sealing remains closed until the active 24-hour endurance passes.
